# Deploying Edgeline

Render (web service) + Neon (Postgres). Both free tiers are sufficient.

The repo ships a `render.yaml` blueprint, so Render provisions the service from
the file rather than from dashboard guesswork.

## 1. Create the database (Neon)

1. Create a project. Any region — pick the one nearest you.
2. Copy the **pooled** connection string (the host contains `-pooler`). It looks
   like:

   ```
   postgresql://USER:PASSWORD@ep-xxxx-pooler.REGION.aws.neon.tech/DBNAME?sslmode=require
   ```

   Keep `?sslmode=require`. The pooled endpoint is PgBouncer in transaction
   mode, which is why the data layer sets `prepare: false` — see
   `server/storage.ts`.

No schema step is needed. The server runs `initSchema()` at boot, which is
idempotent `CREATE TABLE IF NOT EXISTS` DDL, and seeds the demon taxonomy and
default trading styles.

## 2. Create the web service (Render)

1. **New → Blueprint**, point it at this repository. Render reads `render.yaml`
   and creates a service named `edgeline`.
2. Set the variables marked `sync: false` in the dashboard:

   | Variable | Required | Notes |
   |---|---|---|
   | `DATABASE_URL` | **yes** | The Neon pooled string from step 1. |
   | `APP_PASSWORD` | **yes** | The single shared password. See the warning below. |
   | `ANTHROPIC_API_KEY` | one of | Preferred — reads prices off a chart axis more reliably. |
   | `PERPLEXITY_API_KEY` | one of | Fallback if no Anthropic key is set. |

   `NODE_ENV` and `SESSION_SECRET` are handled by the blueprint —
   `SESSION_SECRET` is generated by Render, so don't paste one in.

3. Deploy. First build takes a few minutes; subsequent ones are faster.

> **`APP_PASSWORD` is not optional in production.** When it is unset the auth
> gate disables itself and every `/api` route is open — the whole database is
> your complete trading record. The server logs a warning at boot if you deploy
> without it.

## Why `--include=dev` is in the build command

`render.yaml` sets `NODE_ENV=production`, and npm omits `devDependencies` when
it sees that. `vite`, `esbuild` and `tsx` all live in `devDependencies`, so
without `npm ci --include=dev` the build has no build tools and fails. Don't
"simplify" that flag away.

## Free-tier behaviour

Render's free tier spins the service down when idle, so the first request after
a quiet period takes ~30s to wake. This is expected, not a fault.

Sessions are stored in Postgres (`user_sessions`), not in memory, specifically
so a spin-down does not log you out.

## Verifying a deploy

- `GET /` returns 200 without a cookie — this is what `healthCheckPath` pings,
  so it must stay unauthenticated. The login screen is client-side.
- `GET /api/session` returns `{"authed":false}` before login.
- `GET /api/trades` returns 401 before login, 200 after.

## Known gaps

- No FK from `trades.style_id` to `trading_styles`; integrity is enforced in
  application code. Deleting a style sets its trades' `style_id` to `NULL`
  rather than destroying trade history.
- `drizzle.config.ts` points at a `migrations/` directory that is never
  generated. Bootstrap is `CREATE TABLE IF NOT EXISTS`, so `npm run db:push` is
  not part of the deploy path.
- `rationaleTags` and `playbook` are JSON-in-TEXT, inherited from the SQLite
  schema. They could be `jsonb`.
